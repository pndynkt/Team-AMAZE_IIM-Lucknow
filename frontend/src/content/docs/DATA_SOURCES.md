# Data sources

The competition's sandbox rules require anonymised, open-source or synthetic data. **All data the twin trains on is synthetic and generated by this repository** (`python -m twin.data.generate`, seed 42). No real person's data is used anywhere. The generator's parameters were informed by public sources, listed here so a reviewer can trace every number.

## What the generator produces

| Stream | Content | Shape |
|---|---|---|
| Static EHR (Synthea-shaped FHIR R4) | Patient (masked ABHA), Condition (SNOMED CT: essential hypertension, T2D, CKD, IHD, prior MI, AF, dyslipidaemia, obesity), Observation (LOINC: SBP, DBP, HbA1c, TC, HDL, LDL, TG, BMI, eGFR), MedicationStatement (CCB, ARB, beta blocker, thiazide, statin, metformin, aspirin), FamilyMemberHistory, a synthetic CAD polygenic risk tier | 240 patients; one bundle each in `backend/data/synthetic/fhir/` |
| Dynamic wearable stream | Overnight RHR, nightly RMSSD (ln), sleep minutes and efficiency, deep and REM share, steps, respiratory rate, SpO2, morning home SBP/DBP (when measured), missing-night flag | 240 x 120 days = 28,800 patient-days (28,685 after the new-enrolment patient is truncated) |
| Labels | Strain-episode event days (classic, silent, abrupt subtypes) | 321 episodes |
| Confounders (unlabelled) | Infection-like illness (RHR up, HRV down, BP flat), missed antihypertensive doses (BP up, nothing else), late nights, travel days, device-off blocks | 249 / 833 / 720 / 313 / 30 |
| Freshness | Last sample time by device sync class (hourly, 15-minute, daily; 4% offline) | per patient |

## Sources that informed parameters (not training data)

| Parameter | Source |
|---|---|
| NightSignal-style rule (+3 / +4 bpm over a personal baseline, consecutive nights; 80% sensitivity, 87.7% specificity, median 3 days early for infection) | Alavi et al., *Nature Medicine* 2021, "Real-time alerting system for COVID-19 and other stress events using wearable data" |
| HRV baseline method (lnRMSSD, 7-day rolling mean, 60-day baseline, smallest worthwhile change = 0.5 x CV) | Australian Institute of Sport, HRV best-practice guide |
| Framingham General CVD Risk Profile coefficients (lipid-based) | D'Agostino et al., *Circulation* 2008; the implementation reproduces the paper's worked example (10.5%) |
| Indian device mix (Noise 26.6%, boAt 14.1%, Fire-Boltt 9.7%, Apple about 2%; 91.6% of units under US$50) | IDC India wearables tracker, FY2025 (Mar 2026) and Q2 2026 |
| Alert-fatigue context (fixed thresholds flagged 55.8% of RPM readings vs 9.4% with personal baselines; 57% of BP readings alerted in a telemonitoring programme) | arXiv 2603.09052; *JMIR Medical Informatics* 2025 |
| Hospital early-warning anchors (Epic Deterioration Index AUROC 0.76, median lead 28 h; Dozee tiers, 3-hour snooze, specificity 0.19 to 0.42) | Singh et al., medRxiv 2020; Yadav et al., *Frontiers in Medical Technology* 2024 |
| Fusion design (concatenating EHR and Fitbit features, +8.9% AUROC on average) | All of Us wearables + EHR study, arXiv 2509.22920 (2025) |
| Vendor escalation timings (Apple fall: about 60 s immobility then 30 s countdown; Samsung: 60 s then SOS SMS; Pixel: about 30 s then 60 s) | Apple, Samsung and Google support pages |
| Beta-blocker dampening of heart-rate responses; blunted autonomic responses in diabetes (used for the "silent" subtype) | Standard pharmacology and the diabetic autonomic neuropathy literature; illustrative, not fitted |

## Public datasets a team can plug in (none required to run)

- Synthea (Apache-2.0): run `./run_synthea -p 1000 --exporter.csv.export=true` and load with `twin.data.synthea.load_synthea_csv`.
- MIMIC-IV Demo (ODbL, 100 patients, PhysioNet): schema check for the EHR loader.
- Stanford COVID-19 wearables (Fitbit, Apple Watch, Garmin heart rate and steps): realism check for RHR noise and sync gaps.
- PhysioNet sleep-accel (31 Apple Watch subjects, ODC-By): sleep and HR realism.
- PMData (Fitbit Versa 2, CC BY 4.0): steps and sleep realism.
